# habits Android APK Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the `habits` Dioxus crate as a sideloadable Android APK, with persistence working on-device and the web build unchanged.

**Architecture:** A new `persist` module hides storage behind `get`/`set` with two compile-time backends (wasm32 → localStorage via gloo, native → JSON files; on Android the directory comes from `getFilesDir()` via JNI). The devenv shell gains the Android SDK/NDK and an Android-capable Rust toolchain; `dx build --platform android` produces the APK.

**Tech Stack:** Rust edition 2024, Dioxus 0.7, dioxus-cli (`dx`), devenv (android integration + rust-overlay channel), jni/ndk-context, Gradle (generated by dx).

**Spec:** `docs/superpowers/specs/2026-07-30-habits-android-apk-design.md`

## Global Constraints

- Web build behavior must not change: `dx serve` in `crates/habits` still works, localStorage keys `habits/v2` / `habits/v1` unchanged.
- `cargo build`, `cargo test -p habits` from repo root, and `nix flake check --no-build` must pass after every task.
- Only the `aarch64-linux-android` Android target (no 32-bit/x86).
- Pre-commit hooks must pass; never `--no-verify`. Conventional Commit messages.
- Edition 2024: `std::env::set_var` requires an `unsafe` block.
- Fresh data on Android — no data migration features.

```rust
//! Key/value persistence for [`crate::store`]. Values are serialized as
//! JSON under a string key. Two backends, chosen at compile time:
//! browser localStorage on wasm, files in the app data directory
//! everywhere else (on Android that's the app-private files dir).

use serde::{Serialize, de::DeserializeOwned};

#[cfg(target_family = "wasm")]
mod backend {
    use super::*;
    use gloo_storage::{LocalStorage, Storage};

    pub fn get<T: DeserializeOwned>(key: &str) -> Option<T> {
        LocalStorage::get(key).ok()
    }

    pub fn set<T: Serialize>(key: &str, value: &T) {
        // Quota exhaustion is the only realistic failure; nowhere to
        // report it, same policy as the pre-split code.
        let _ = LocalStorage::set(key, value);
    }
}

#[cfg(not(target_family = "wasm"))]
mod backend {
    use super::*;
    use std::path::PathBuf;

    pub fn get<T: DeserializeOwned>(key: &str) -> Option<T> {
        let text = std::fs::read_to_string(path_for(key)).ok()?;
        serde_json::from_str(&text).ok()
    }

    pub fn set<T: Serialize>(key: &str, value: &T) {
        let path = path_for(key);
        if let Some(dir) = path.parent() {
            let _ = std::fs::create_dir_all(dir);
        }
        if let Ok(json) = serde_json::to_string(value) {
            let _ = std::fs::write(path, json);
        }
    }

    /// Keys may contain `/` (e.g. "habits/v2"); flatten to one file name.
    fn path_for(key: &str) -> PathBuf {
        data_dir().join(format!("{}.json", key.replace('/', "-")))
    }

    #[cfg(target_os = "android")]
    fn data_dir() -> PathBuf {
        android_files_dir().unwrap_or_else(|| PathBuf::from("."))
    }

    /// The app-private files dir, via JNI: `context.getFilesDir()`.
    /// Dioxus doesn't expose the Android context in its public API yet,
    /// so this goes through ndk-context (the documented workaround).
    #[cfg(target_os = "android")]
    fn android_files_dir() -> Option<PathBuf> {
        let ctx = ndk_context::android_context();
        let vm = unsafe { jni::JavaVM::from_raw(ctx.vm().cast()) }.ok()?;
        let mut env = vm.attach_current_thread().ok()?;
        let context = unsafe { jni::objects::JObject::from_raw(ctx.context().cast()) };
        let files_dir = env
            .call_method(context, "getFilesDir", "()Ljava/io/File;", &[])
            .ok()?
            .l()
            .ok()?;
        let path: jni::objects::JString = env
            .call_method(&files_dir, "getAbsolutePath", "()Ljava/lang/String;", &[])
            .ok()?
            .l()
            .ok()?
            .into();
        let s = env.get_string(&path).ok()?;
        Some(PathBuf::from(s.to_str().ok()?.to_string()))
    }

    #[cfg(not(target_os = "android"))]
    fn data_dir() -> PathBuf {
        std::env::var_os("HABITS_DATA_DIR")
            .map(Into::into)
            .unwrap_or_else(|| PathBuf::from("."))
    }
}

pub fn get<T: DeserializeOwned>(key: &str) -> Option<T> {
    backend::get(key)
}

pub fn set<T: Serialize>(key: &str, value: &T) {
    backend::set(key, value)
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn file_backend_round_trips() {
        let dir = std::env::temp_dir().join(format!("habits-persist-{}", std::process::id()));
        std::fs::create_dir_all(&dir).unwrap();
        // SAFETY: the only test (and only code) mutating the environment.
        unsafe { std::env::set_var("HABITS_DATA_DIR", &dir) };

        assert_eq!(get::<Vec<u32>>("habits/test"), None);
        set("habits/test", &vec![1u32, 2, 3]);
        assert_eq!(get::<Vec<u32>>("habits/test"), Some(vec![1, 2, 3]));

        // The key's slash was flattened into the file name.
        assert!(dir.join("habits-test.json").exists());
        let _ = std::fs::remove_dir_all(&dir);
    }
}
```

        if let Some(data) = persist::get(KEY) {
            return data;
        }

        let migrated: Self = persist::get(V1_KEY)
            .map(Self::from_v1)
            .unwrap_or_default();

            migrated.save();
        }
        migrated
    }

- [ ] **Step 1: Release build for Android**

Run (inside the devenv shell):

```bash
cd crates/habits

```

Watch the log: dx should report enabling the crate's `mobile` feature automatically. If it doesn't, re-run as `dx build --platform android --release --no-default-features --features mobile`.
Expected: Gradle project generated and built; on success find the APK with
`find ../../target/dx/habits -name '*.apk'` (docs place it under `target/dx/habits/release/android/app/app/build/outputs/apk/`).

Known NixOS failure modes and their fixes (spec risk #1):
- aapt2 errors → devenv already exports a `GRADLE_OPTS` aapt2 override; make sure the build runs inside `devenv shell`.
- `JAVA_HOME` unset / "Failed to write main executable" → add `languages.java.enable = true;` to `devenv.nix` and re-enter the shell.
- Gradle wanting a missing build-tools/platform version → add that exact version to `android.buildTools.version` / `android.platforms.version` in `devenv.nix`.

- [ ] **Step 2: Check the APK's signature**

Run:

```bash
"$ANDROID_HOME"/build-tools/34.0.0/apksigner verify --print-certs <path-to-apk> && echo SIGNED
```

Expected: either `SIGNED` (done — go to Step 4) or an "unsigned" error (go to Step 3).

- [ ] **Step 3 (only if unsigned): sign with a local debug keystore**

```bash
keytool -genkeypair -keystore ~/.android/habits-debug.keystore \
  -alias habits -keyalg RSA -keysize 2048 -validity 10000 \
  -storepass android -keypass android -dname "CN=habits debug"
"$ANDROID_HOME"/build-tools/34.0.0/zipalign -f -p 4 app-release-unsigned.apk habits.apk
"$ANDROID_HOME"/build-tools/34.0.0/apksigner sign \
  --ks ~/.android/habits-debug.keystore --ks-pass pass:android habits.apk
"$ANDROID_HOME"/build-tools/34.0.0/apksigner verify habits.apk && echo SIGNED
```

The keystore lives under `~/.android/`, outside the repo — nothing to gitignore. If any keystore ends up inside the repo instead, add its path to `.gitignore` before committing anything.
Note: re-installing over an app signed with a *different* key fails with `INSTALL_FAILED_UPDATE_INCOMPATIBLE` — uninstall first, and keep using this keystore for future builds.
